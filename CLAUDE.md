# Vuho speech-to-text app

WisprFlow clone local-first, fully private.
macOS Apple Silicon (ANE, Metal) is the product today. Linux (Sway/Wayland first) is a second platform in progress (ADR-024): the STT engine and the `test-stt-ffi` gate run there, the UI and OS integration do not yet.

100% native integration

1. User activates STT with a global key, always-on-top semi-transparent overlay appears, featuring partial transcription and simple lines waveform
2. STT language always matches OS-native keyboard input method
3. User confirms session end with the hotkey, the app does rule-based text cleanup (filler removal, spacing normalization, newline collapse — see `vuho-postprocess`) and inserts the text into the active window, at the cursor position (so the vuho's own overlay should not grab the focus).
4. The text should be natively send to the focused app, e.g. clipboard + <Cmd>+V keystroke on MacOS

## Commands

- Build (macOS): `cargo build --release -p vuho-ui` — no Swift toolchain required (native CoreML via `objc2-core-ml`). `vuho-ui`, `vuho-os-integration` and `vuho-dictation` build on macOS only.
- Run overlay demo (no mic, no engine): `cargo run -p vuho-ui --features demo`
- Test: `cargo test` (workspace). Single test: `cargo test -p vuho-os-integration map_en_us`. `vuho-ui`'s demo-feature build has its own, separately-compiled test set (different `#[cfg]` surface, e.g. `panel::PanelRoot`'s demo-only `Render` impl and `create_panel` overload) — also run `cargo test -p vuho-ui --features demo` to cover it; plain `cargo test` alone does not. Note: nextest was planned but is NOT installed — use plain `cargo test`.
- **Linux** (ADR-024): the toolchain lives in `devbox.json` (Rust 1.98.1 via rustup into a project-local `.devbox/`, plus ALSA, OpenSSL, Wayland, xkbcommon, Vulkan, fontconfig, python3), and `rust-toolchain.toml` pins the same 1.98.1. Every Linux command runs as `devbox run -- cargo …` or inside `devbox shell`. Provision the model with `devbox run -- ./scripts/fetch-model.sh parakeet-tdt-0.6b-v3-onnx` (the manifest's Linux default), then `devbox run -- cargo run --release -p test-stt-ffi` must print `PASS` (a debug build also passes, but loads in ~4 s and needs 0.4–1.0 s per window). Linux-ready crates, the set CI's `ubuntu-24.04` job runs fmt, `clippy -D warnings` and tests over (`LINUX_CRATES` in `.github/workflows/ci.yml`): `vuho-domain`, `vuho-postprocess`, `vuho-model-paths`, `vuho-settings`, `vuho-model-fetch`, `vuho-audio`, `vuho-stt-engine`, `test-stt-ffi`; run the same set locally with `devbox run -- cargo test -p <crate> …`. Canary and voz are macOS-only models: `--model canary-1b-v2` / `--model voz` on Linux fail with `EngineError::ModelForOtherOs`.
- Lint: `cargo clippy --workspace --all-targets` (workspace lints enable `clippy::pedantic` at `warn`).
- STT batch regression gate: `cargo run -p test-stt-ffi` must print `PASS` (transcribes `jfk.wav`
  with the manifest's default model; override the audio with `JFK_WAV`). `cargo run -p test-stt-ffi -- --model canary-1b-v2`
  and `-- --model voz` run the same gate against the other two backends (ADR-022, ADR-023) — each must print `PASS`.
- Model provisioning (idempotent, pinned revisions): `./scripts/fetch-model.sh <model-id>` for one
  STT model, `./scripts/fetch-model.sh silero` for the VAD weights, or `./scripts/fetch-model.sh all`
  (the default when no argument is given) for every STT model plus Silero. A model **absent from
  `models.lock.json`** is bootstrapped rather than refused (ADR-023): the files are fetched, the hash
  check is skipped, the script prints `UNLOCKED` and is documented to exit **non-zero** after the files land (one Linux run exited 0 — unverified discrepancy, see `TODO.md`) — run
  `./scripts/lock-model.sh <id>` and commit the lock, and the next fetch is a verified no-op. A
  locked model is verified exactly as before.
- Package a signed `.app`: `./scripts/package.sh` (delegates to `scripts/bundle-macos.sh`; ad-hoc signature by default, set `SIGN_ID` for a stable identity so TCC grants survive rebuilds). `VUHO_BUNDLE_MODEL=0` embeds no model at all; `VUHO_BUNDLE_MODELS` is a space-separated list of model ids to embed, defaulting to the manifest's `default_model` alone — so widening the DMG to more than one model is explicit (`VUHO_BUNDLE_MODELS="parakeet-tdt-0.6b-v3 canary-1b-v2 voz"`), never accidental.
- **Release: the git tag is the version.** Push `vMAJOR.MINOR.PATCH` (e.g. `v0.9.0`) and `.github/workflows/release.yml` does the rest — it validates the tag's *shape* (a 2-component `v0.9` is rejected), then feeds that one string to the bundle's `CFBundleShortVersionString` (as `VUHO_VERSION`, which `bundle-macos.sh` prefers over `cargo metadata`), the tarball name, and the Homebrew cask. **Never bump `Cargo.toml`'s version**: it is pinned at the `0.0.0-dev` sentinel deliberately, since nothing reads `CARGO_PKG_VERSION` and `publish = false` — a real number there would only be a second copy of the tag to keep in sync. Local/CI builds leave `VUHO_VERSION` unset and stamp `0.0.0-dev`, a self-identifying not-a-release marker.
- **The Homebrew cask publishes itself.** After uploading the release, `release.yml` fires a `repository_dispatch` (`event_type: vuho-release`) at `aka-rider/homebrew-tap`, whose `release-vuho.yml` re-downloads the published asset, computes the `sha256` from it, and pushes `Casks/vuho.rb` — so the checksum users verify is derived from the artifact actually being served, not restated from the builder's belief. Requires a `HOMEBREW_TAP_TOKEN` secret (fine-grained PAT, `contents: write` on the tap); without it the dispatch step is a no-op and the job summary prints the one-line `gh workflow run` fallback. **If a release ever ships without a cask update, check that secret first** — expiry is the expected failure mode.

## Architecture

Cargo workspace of eleven crates, no Swift/FFI — on macOS the STT engine is native CoreML via `objc2-core-ml`, on Linux it is ONNX Runtime via `ort` (ADR-024). The data flow below describes macOS, the only platform with a UI today:

| Crate | Purpose |
|---|---|
| `vuho-domain` | Pure domain types & events (`DictationEvent`, `DictationCommand`, `ModelStatus`); no deps, no platform code |
| `vuho-audio` | cpal capture thread + rubato resample to 16 kHz mono; owns the microphone (ADR-013) |
| `vuho-stt-engine` | Four selectable backends behind one `WindowInference` seam (ADR-022, ADR-023, ADR-024) — three CoreML on macOS, one ONNX Runtime on Linux — built through the single `load_engine` constructor: `ParakeetEngine` (Parakeet-TDT `CoreML` components, greedy TDT decode over a sliding 15 s window), `CanaryEngine` (Canary-1B-v2, greedy attention encoder-decoder, no KV cache, CPU-only) and `VozEngine` (Desert Ant Labs' fp16 re-export of the same Parakeet-TDT weights: `mel` + `encoder` + a fused decoder that scores 8 encoder frames per call, macOS 15+) and `OnnxParakeetEngine` (Linux: the same Parakeet-TDT weights as int8 ONNX, CPU). `StreamingEngine<M>` owns the shared batch/streaming lifecycle; Silero VAD via `voice_activity_detector` |
| `vuho-dictation` | Session orchestration: `DictationSession` + `DictationPipeline` (explicit Idle/Recording state machine) |
| `vuho-postprocess` | Rule-based text post-processing: filler removal, spacing normalization, newline collapse; no external deps beyond `vuho-domain` |
| `vuho-os-integration` | macOS via objc2: clipboard, ⌘V injection, TIS keyboard-language detection, CapsLock/chord hotkey (CGEventTap) |
| `vuho-settings` | Serde-only settings persistence: `HotkeySetting` preset, microphone device name, and `speech_model: Option<String>` (`None` = the manifest's default), atomic load/save |
| `vuho-model-paths` | Std-only chokepoint crate (ADR-019, ADR-024): embeds `models.manifest.json` and `models.lock.json` at compile time, exposes typed accessors + the single `resolve_model_folder` env-var → bundle → workspace-dev → user-data (ADR-020) resolution chain (the bundle step is macOS-only), plus the shared `atomic_write` helper, and is the one OS-identity chokepoint for the data crates (`Os`, `HOST_OS`, `Requires`, `MacosVersion`) |
| `vuho-model-fetch` | The only crate permitted to perform network I/O (ADR-020): `availability(model_id)`/`availability_all() -> ModelAvailability` (sidecar-and-lock verification, scoped to the user-data candidate only; each row carries a `Support { Supported, NeedsMacos(version), OtherOs(os) }` from `os_support.rs`), `download(model_id, …)` (hf-hub 1.0, Xet-first with HTTPS fallback), and `delete(model_id)` — refused for anything Vuho did not download itself |
| `vuho-ui` | macOS only for now. GPUI: a single always-on-top, always-mouse-interactive panel painted one way — a tabbed Overlay/Settings window whose height follows the active tab (ADR-021) — plus the menu-bar status item; produces the `vuho` binary |
| `test-stt-ffi` | Batch STT regression binary (the `PASS` gate above) |

Data flow: hotkey trigger (CGEventTap thread in `vuho-os-integration/src/hotkey.rs` — CapsLock by default, or a configured chord). CapsLock is **level-triggered**, not edge-triggered (ADR-007): the LED is the source of truth, so a rising `MaskAlphaShift` edge sends `DictationCommand::Start` and a falling edge sends `Stop` (`caps_lock_command`) — a dropped/discarded command desyncs the LED from the session for at most one tap and self-heals rather than permanently inverting the mapping, as an undifferentiated `Toggle` used to. The configured chord still sends `Toggle` (a momentary gesture with no external LED state to track), as does the status-bar menu. Either way, the command travels over a crossbeam channel → `DictationPipeline` starts a session: detects language via the injected `detect_language` policy (TIS in production), reads the configured microphone device from `SettingsStore`, starts streaming capture, forwards `PartialTranscript`/`Activity` events to the UI. `SessionStarted` is emitted **only after** `start_stream` succeeds, so the panel's Overlay tab/waveform never implies listening that isn't happening — `apply_events` therefore also shows the panel (via `panel::on_session_started`) on `Error`, or a failed start would render into a hidden window. On stop: `vuho_postprocess::postprocess(text, language)` (filler removal, spacing normalization, newline collapse) → clipboard + synthesized ⌘V (`inject_text`; Secure Input yields `OsError::SecureInputActive`) → `SessionCompleted`. A backend that cannot transcribe the detected language (Canary supports 25; Parakeet and voz take any — voz has no language prompt, so it has no such path) fails at `start_stream` with `EngineError::UnsupportedLanguage`, which the pipeline turns into a recoverable `DictationEvent::Error` and **no** `SessionStarted` — never a silent fallback to another language.

The Settings tab's Speech Model card is a **list of every model the manifest knows** (Parakeet, Canary, voz, and the Linux-only ONNX Parakeet), not one model's status (ADR-022, ADR-023): a combobox picks the active one (options that are not `Ready` **and** supported by this macOS render unselectable, and the whole control locks while recording), a line under it names the languages that model can actually reach (`reachable_languages`: Canary's 25 intersected with what the OS layer can report; Parakeet and voz the whole OS-mapped set), and one row per model carries its size plus the single control its state calls for — Download / progress / Verifying / Retry / "Selected" / Delete / a "Bundled"-"Dev tree"-"Override" pill saying why Delete is absent / "Needs macOS 15" (Canary **and** voz) / "Linux only" or "macOS only" (`Support::OtherOs`: the macOS list shows the ONNX Parakeet as "Linux only"), plus a credit line where the manifest carries an `attribution` (voz: "Powered by Desert Ant Labs"; `settings_tab::attribution_label`). The rows come from `StatusModel::models`, filled only by `UiCommand::ModelList`, which the provisioning thread emits after **every** transition. Selecting a model sends `ProvisionCommand::SelectModel(id)`; the provisioning thread persists `speech_model`, drops the `DictationSession`, reloads the engine, and drains stale dictation commands so a hotkey press during the reload cannot leave the CapsLock LED on with no session behind it.

> **Streaming is wired**: `ParakeetEngine::start_stream` prechecks mic permission, starts `vuho-audio` capture, and spawns the `"vuho-stt-session"` thread (VAD-gated ≥1 s adaptive partials, `Activity` from capture RMS every ~50 ms, ≥800 ms silence endpoint promotion, end-aligned final window on stop). Decoder state is **fresh per window** — never carried across windows (carry causes blank-lock; continuity comes from the 2 s audio overlap + word-level seam merge, see ADR-015). `stop_stream` on an idle engine returns `EngineError::NoActiveStream`.

Key facts:

- **Audio capture is owned by `vuho-audio`** (ADR-013, superseding the retired WhisperKit-owned-capture design): a dedicated `cpal` thread resamples to 16 kHz mono via `rubato`. The waveform is cosmetic, driven by capture-thread RMS. Device *selection* is by name, resolved via `cpal::default_host().input_devices()`.
- Entry point: `crates/vuho-ui/src/main.rs`. `run_production` builds the settings store, the `StatusModel`/`SettingsTab` entities, and the panel (`panel::create_panel`) up front, then checks `readiness::missing_permissions()`: if anything is missing, the panel opens on its Settings tab and startup stops there (a relaunch is required once every grant lands) — `wiring::wire_production` never runs on that path. Otherwise `wire_production` creates the `DictationSession`, starts the `HotkeyListener` with the persisted preset (connecting it into the already-built `SettingsTab` via `connect_hotkey`), and installs the status-bar menu (Start/Stop, Open Vuho, Quit). There is no process-lifetime settings `Global` — the settings store, hotkey listener, and command channel are held by `SettingsTab`/`wiring::wire_production` directly. Quit hotkey is `Cmd+Option+Shift+Q`; `Cmd+,` opens the panel on its Settings tab (the app is `LSUIElement`: no Dock icon, accessory activation policy, non-activating panel).
- Settings: `~/.config/vuho/settings.json` (or `$XDG_CONFIG_HOME/vuho/settings.json`), written atomically (temp file + rename); a malformed file logs a warning (surfaced in the Settings tab via `StatusModel::settings_load_warning`) and falls back to defaults without touching the file. Changing the hotkey in the Settings tab rebinds the listener **live** (`stop()` + `start()`); changing the microphone applies at the next session start; changing the model (`speech_model: Option<String>`, `None` = the manifest's `default_model`) reloads the engine immediately. `CURRENT_SETTINGS_VERSION` was **not** bumped for `speech_model`: `migrate` discards the whole file on a version mismatch, so a bump would silently reset every user's hotkey and microphone — a `#[serde(default)]` field is additive-safe on its own.
- **No FFI, no dylib**: the Parakeet-TDT model components are `.mlmodelc` bundles loaded directly via `objc2-core-ml`'s `MLModel::modelWithContentsOfURL_configuration_error` — no Swift, no `libloading`, no C ABI boundary. `RNNTJoint.mlmodelc`'s real `model.mil` signature takes exactly `encoder_outputs`/`decoder_outputs` (no `encoder_length`, despite early planning notes assuming one); its `logits` output is post-softmax log-probabilities, not raw logits — immaterial for greedy argmax decoding.
- **The engine is app-scoped, loaded once per selected model** (CONSTITUTION rule 3): `ParakeetEngine::load(model_id, folder)` / `CanaryEngine::load(model_id, folder)` / `VozEngine::load(model_id, folder)` / `OnnxParakeetEngine::load(model_id, folder)` are the only constructors, and `vuho_stt_engine::load_engine(model_id, folder) -> Box<dyn TranscriptionEngine + Send>` is the single chokepoint in front of them (ADR-024); there is no `init`/`load_models` step, so an unloaded engine is unrepresentable. `host_backend(&SttModel) -> Option<HostBackend>` is the one place a manifest `Backend` meets the running OS (`HostBackend` has per-OS variants: macOS `ParakeetTdt`/`CanaryAed`/`VozTdt`, Linux `ParakeetTdtOnnx`); `None` means the model is for the other OS and `load_engine` returns `EngineError::ModelForOtherOs`. A test asserts `host_backend(m).is_some() == (m.requires.os() == HOST_OS)` for every manifest model. `wiring::load_engine_and_session` and `test-stt-ffi` both go through `load_engine`. `wiring::selected_model_id` is the single place that reads `speech_model` and resolves `None`, an unknown id, or a model of the other OS (no `host_backend`) to the host's default model, with a `log::warn!` for the last two; the provisioning loop, the Settings combobox and `load_engine_and_session` all call it. `wire_production` warms it on a background thread (status bar shows `Loading model…`) and only then builds the `DictationSession`; presses during warmup are discarded. `ParakeetModels::load` also runs one warmup inference on a zeroed 15 s window to trigger `CoreML`'s ANE plan compilation for `ParakeetEncoder_15s` (the only component loaded with `CpuAndNeuralEngine` — `ParakeetDecoder`/`RNNTJoint` have `RangeDims`-flexible inputs and are CPU-only; loading them with the ANE enabled produces a `CoreML` E5RT validation error at prediction time). **Measured warmup time on this development machine: ~50ms** (`ParakeetModels::load`'s `log::info!` line) — but every measurement taken during this work was against a machine whose CoreML ANE compilation cache was already warm from many prior runs in the same session; a genuine first-ever cold-compile number (which the retired WhisperKit path measured at 136s) was not obtainable without clearing the system-wide CoreML cache, which risks affecting other apps and was judged out of scope. Re-measure on a truly clean machine/cache before trusting a cold number here.
- **Model resolution is a Rust chokepoint, one level deeper than before (ADR-019)** — `vuho_stt_engine::resolve_model_folder(model_id)` is a thin wrapper that builds a `vuho_model_paths::ModelSpec` for that model from the embedded `models.manifest.json` and delegates to `vuho_model_paths::resolve_model_folder()`, the **single** copy of the env-var → the enclosing `.app`'s `Contents/Resources/<name>` → the workspace-relative `models/<name>` → the user-data `models/<name>` (ADR-020; `~/Library/Application Support/Vuho/models` on macOS, `$XDG_DATA_HOME/vuho/models` else `~/.local/share/vuho/models` on Linux; the `.app` candidate exists on macOS only) fallback chain → `EngineError::ModelFolderMissing`. `vuho_model_paths::resolve_model()` returns the same answer plus the `ModelSource` that produced it, which is how ADR-020's "Vuho owns only the bytes it fetched" invariant is carried rather than re-derived from a path prefix. Vuho's own Rust code never downloads a model at runtime from inside this chokepoint — only `vuho-model-fetch`, gated behind an explicit user action, ever performs network I/O (ADR-020). Every engine takes the already-resolved folder, so an engine without one is unrepresentable.
- **Component filenames live only in the manifest (ADR-019/ADR-022/ADR-023).** `stt.models.<id>.assets` is a **named-role** map (`preprocessor`, `encoder`, `decoder`, `joint`, `projection`, `vocab`, `embedding`, `meta` — a model uses the subset its backend needs; voz has no `joint`), and `vuho_stt_engine::asset_path(model_id, role, dir)` is the one place a role becomes a file. Before this, `parakeet/models.rs` hardcoded five filenames while `validate_model_layout` read the manifest — two lists, nothing tying them together.
- **The manifest is platform-aware (ADR-019 amended by ADR-024).** Each model carries `requires`, `{"os":"macos","min_version":"15.0"}` or `{"os":"linux"}`, which replaced `min_macos` and is parsed into `vuho_model_paths::Requires`/`MacosVersion` at deserialize, so a malformed floor fails at manifest load. `default_model` is per OS (`{"macos": "parakeet-tdt-0.6b-v3", "linux": "parakeet-tdt-0.6b-v3-onnx"}`) and `SttManifest::default_model()` returns the running host's. Data crates that need the OS use `vuho_model_paths::{Os, HOST_OS}` rather than their own `cfg`.
- **`vuho-stt-engine` has one compile-time OS fork (ADR-024).** It lives in `lib.rs` (plus `canary/mod.rs` and `parakeet/mod.rs`, which mix CoreML and OS-neutral code): the CoreML backends, `mic_permission` (the AVFoundation probe; Linux has no permission concept) and `EngineError::CoreMl` are macOS-only, `EngineError::Onnx` and the ONNX engine are Linux-only, and there are no stubs for the other OS (the old `not_macos` stub in `coreml.rs` is gone). `StreamingEngine<M: WindowInference + Send + Sync>` holds an `Arc<M>`; the CoreML `SendModel` (per-type `unsafe impl`s) delegates `WindowInference`, the ONNX models are `Send + Sync` through a `Mutex` per `ort::Session`. The TDT decode loop is generic over `TdtStep { type State; start; score; accept }` (ADR-015 amended): `score` never advances the prediction network, `accept` does and is called on non-blank emissions only, blank frames call only `score`. CoreML primes with BLANK in `start`, runs the joint in `score` and the decoder in `accept` (the same call sequence as before); ONNX runs the fused graph in `score`, which parks the new `h`/`c`, and `accept` commits them. `DecoderState` (`{h, c, dec_out}`, `zeroed()`) is now `pub(crate)` and macOS-only.
- Env vars (names themselves live in `models.manifest.json`, not hardcoded in Rust or the scripts): `VUHO_MODEL_FOLDER`, `VUHO_MODEL_NAME` (defaults to the selected model's `dir_name`), `JFK_WAV`. Both overrides apply to whichever model is being resolved, so they point at one model tree at a time. There is no "must match" comment to keep in sync anymore — the manifest is the one place these strings are written down; the provisioning/packaging scripts read the same file via `scripts/manifest-lib.sh`.
- **Two distribution shapes, one build script (ADR-020/ADR-022):** measured on disk, Parakeet TDT 0.6B v3 is **473 MB** (dominated by `ParakeetEncoder_15s.mlmodelc`'s weights) and Canary 1B v2 is **543 MB** and voz is **463 MB** (485,338,884 bytes locked, 16 files — the panel's decimal-MB figure is 485; likewise Parakeet 496 and Canary 569 there); Silero VAD is 1.1 MB and is never bundled. A model can either be embedded — provisioned out-of-band via `./scripts/fetch-model.sh <id>` into `models/` (gitignored) and copied into `Contents/Resources/` by `scripts/bundle-macos.sh` (`VUHO_BUNDLE_MODEL=1`, the DMG build, offline from first launch) — or omitted (`VUHO_BUNDLE_MODEL=0`, the Homebrew-cask build, measured ≈40 MB on disk / ≈15 MB as the gzipped release tarball), in which case `vuho-model-fetch` downloads it into `~/Library/Application Support/Vuho/models/` on first run, gated by an explicit Download button in the panel's Settings tab and verified against the committed `models.lock.json`. **The DMG embeds only `VUHO_BUNDLE_MODELS` (default: the manifest's `default_model`)** — Parakeet alone, ≈500 MB, unchanged — so embedding more than one model is an explicit widening of that variable, not a side effect of adding Canary or voz.
- **Canary and voz need macOS 15; Parakeet does not.** Canary's encoder/decoder are int4; voz's bundles are `<ios18>` programs and it selects its decoder function through `MLModelConfiguration.functionName` (macOS 15 API, sent as a plain Objective-C message so the binary still launches on 14). Each model declares its floor as `requires.min_version` in the manifest. `vuho-model-fetch` compares that against the running system (`NSProcessInfo::isOperatingSystemAtLeastVersion`) and reports `Support::NeedsMacos(version)` (`Support::OtherOs` for a model built for the other OS), so a macOS 14 user sees a "Needs macOS 15" row instead of a 543 MB (Canary) or 485 MB (voz) download that cannot run. The project floor stays 14.0+.

## The Stack

- Rust; GUI framework gpui 0.2.2 https://gpui.rs/
- Transcription, default: Parakeet-TDT (`FluidInference/parakeet-tdt-0.6b-v3-coreml`, itself a `CoreML` export of `nvidia/parakeet-tdt-0.6b-v3`) loaded directly via `objc2-core-ml` — a hand-rolled greedy TDT decode loop (`vuho-stt-engine/src/parakeet/tdt.rs`) over Preprocessor → Encoder → (Decoder + Joint) per 15 s sliding window. WhisperKit (Swift, FFI/`libloading`) was retired: out of the project's control and the main source of instability. whisper-rs was rejected before that: no streaming.
- Transcription, optional second backend (ADR-022): Canary-1B-v2 (`FluidInference/canary-1b-v2-coreml`, a `CoreML` int4 export of `nvidia/canary-1b-v2`) — an attention encoder-decoder with **no KV cache**: `vuho-stt-engine/src/canary/aed.rs` resubmits the whole `[1, S]` token tensor on every greedy step, reads the hidden row at `pos - 1`, projects it, and takes an argmax over 16 384 ids, stopping at EOS 3. It must be *told* the source language (25 supported, `canary::prompt`), so an unsupported one is a typed error rather than a guess. `S` is read from the model, never hardcoded. All four components load **CPU-only** — see ADR-022 for the ANE finding, which is unresolved, not settled. **Measured on this development machine: one 15 s window ≈ 800 ms** (`canary_batch`'s own `println!`, re-measured at 813 ms while writing this), Canary load ≈ 4 s, `stop_stream` → final text ≈ 803 ms.
- Transcription, optional third backend (ADR-023): voz (`desert-ant-labs/voz`, pinned revision `e11906fe59d1ce9882eb8e82ed59f78bdc8e6153`, not gated on HF) — Desert Ant Labs' compiled `CoreML` re-export of **the same** NVIDIA Parakeet-TDT 0.6B v3 weights as the default, as three fp16-I/O `<ios18>` bundles: `mel.mlmodelc` (STFT + log-mel; the host frames the audio into `audio_rows [1,160,1,1503]` + `mel_mask`, `voz/frontend.rs`), `encoder.mlmodelc` (6-bit palettized, the joint's encoder projection folded in, output `enc_proj [1,640,1,188]`; its `pad_mask` input **must stay all ones** — zeroing it explodes BatchNorm, a vendor quirk — and the attention mask is the additive `key_bias`), and a multifunction `decoder.mlmodelc` (`main` = 16 lanes, `decoder_8/4/2/1`; Vuho loads `decoder_1` via `CoreMlModel::load_function`) with the 2-layer LSTM prediction net, joint and token/duration heads fused into one call over an 8-frame `enc_step`. The LSTM `h`/`c` are explicit tensors (no `MLState`); the token embedding is a host-side lookup into `embedding.f16` (`[8193, 640]`, row 8192 = blank). All geometry comes from the shipped `meta.json`, which is cross-checked at load against 14 tensor shapes the loaded models declare (a mismatch is `LoadFailed` naming the tensor) — `vocab.json` is a plain JSON array, which `Vocab::load` now accepts alongside the id-keyed map. ## Platform & testing notes

- Product platform: Apple Silicon macOS 14.0+; Metal (via GPUI) required to build the UI. No Swift toolchain required — the macOS STT engine is native CoreML via `objc2-core-ml`.
- Linux (ADR-024, in progress): only the Linux-ready crates listed under Commands build and run there (STT engine, model fetch, audio, settings, postprocess, the `test-stt-ffi` gate). There is no microphone permission concept (`mic_permission` is macOS-only). Models live under `$XDG_DATA_HOME/vuho/models` (else `~/.local/share/vuho/models`). Canary and voz are macOS-only. `vuho-ui`, `vuho-os-integration` and `vuho-dictation` are not built on Linux yet; the planned pieces (layer-shell overlay, `vuho --toggle`, wl-clipboard paste, Sway IPC layout detection) are listed in ADR-024 and `TODO.md`, not implemented. `tests/onnx_batch.rs` (Linux-only, model-gated, skips cleanly without `models/`) is the ONNX counterpart of `batch_multiwindow.rs`: jfk.wav transcribes to the quote and jfk×3 holds each half exactly three times.
- Accessibility and Input Monitoring are runtime TCC grants, not entitlements — the only entitlement is `com.apple.security.device.audio-input`. macOS prompts on first launch; reset with `tccutil reset Microphone|Accessibility|InputMonitoring tech.iurii.vuho`.
- Unit tests live inline (`#[cfg(test)] mod tests`). Tests touching macOS APIs (clipboard, TIS) tolerate failure in headless environments; `vuho-dictation` pipeline tests inject a local fake `TranscriptionEngine` via `new_with_engine` (trait-only coupling). `vuho-stt-engine`'s own pure modules (`parakeet::tdt`, `stream::windower`, `stream::merge`, `vocab`, `canary::prompt`, `canary::aed`, `voz::tdt`/`frontend`/`meta`/`embedding`) unit-test without the model; a handful of tests (`coreml::tests`, `vad::tests`, `tests/batch_multiwindow.rs`, `tests/canary_batch.rs`, `tests/voz_batch.rs`, the two streaming stop-latency tests in `stream::session`) are model-gated and skip cleanly (with an `eprintln`, not a failure) when `models/` is absent.
- Real mic streaming is only exercised via `#[ignore]` tests (`streaming_smoke`); the deterministic gate is the `test-stt-ffi` binary, which covers batch transcription for **any** of the three backends (`--model <id>`). `tests/batch_multiwindow.rs` (Parakeet), `tests/canary_batch.rs` (Canary) and `tests/voz_batch.rs` (voz) all run un-ignored (model-gated, skipping cleanly without `models/`) and verify no dropped or duplicated content at the window seams (jfk×3: each half of the quote exactly three times); `canary_batch` additionally checks every Canary prompt/EOS constant against the shipped `vocab.json`/`metadata.json` rather than against its own table, and prints the wall clock of one 15 s transcribe; `voz_batch` cross-checks `meta.json`/`vocab.json` against the shipped files and asserts no `<|…|>` special leaks into a transcript. The stop → final-text latency is measured for Canary and voz by `canary_streams_jfk_wav_…` / `voz_streams_jfk_wav_and_reports_its_stop_to_result_latency` (one shared helper, `stream_jfk_and_report_stop_latency`). The `merge` no-match fallback reconciles a fresh word the seam cuts with `committed`'s last word (`merge_without_word_run`, ADR-023): committed's last word a non-empty strict prefix of it → fresh's complete copy replaces it; equal or unrelated → fresh's copy is dropped whole. A rule checked before those, `extends_cut_word` (ADR-024, found by the int8 ONNX decode on jfk×3), handles the mirror case: when `committed`'s last word strictly extends the first `fresh` word that starts at (or one frame before) its own position, within `tolerance`, i.e. the window edge cut the word and the decoder guessed an ending ("ask" heard as "asked"), `fresh`'s copy replaces `committed`'s guess from that word onward. The candidate is only ever that one fresh word — an earlier fresh prefix ("I" before a committed "it") must not fire, or the words between would be replayed. The prefix rule is a general seam-robustness fix that voz exposed ("asksk" from jfk×3, whose cause was voz's window-1 decode missing "not" at the window edge, not offset positions), applies to every backend, and is pinned by five specifications in `stream::merge` (plus four for `extends_cut_word`). The stride probe (`coreml::tests`, `#[ignore]`d) is what reports the encoder's real strides against a real bundle: `cargo test -p vuho-stt-engine -- --ignored canary_stride_probe --nocapture`.

## Known Issues

- **`CoreML` pads an array's last dimension, and a dense read of a padded array returns silent garbage — not an error.** Measured by the `canary_stride_probe` against the shipped bundle: the Canary encoder declares `[1, 1024, 188]` but reports `strides = [196608, 192, 1]` — the last dimension padded 188 → 192. `MlArray::to_f32_vec_into` computes its length as `shape().iter().product()` and does a flat `copy_nonoverlapping`, so for such an array it would copy misaligned data and report success. Every read of a possibly-padded output must go through `MlArray::strides` + `gather_f32_into`, which expresses the read as an offset list and turns an offset past the buffer `CoreML` reports into a typed error. Voz is a second data point, measured on its shipped bundle: `enc_proj` declares `[1, 640, 1, 188]` and reports strides `[122880, 192, 192, 1]` (188 → 192), the decoder's `logits` declares `[1, 8198, 1, 8]` and reports `[262336, 32, 32, 1]` (8 → 32), and `h_out`/`c_out` report `[40960, 32, 32, 1]` for a declared `[1, 1280, 1, 1]` (1 → 32) — so even a single column is padded. Voz reads every output through `column_major_offsets` + `gather_f32_into`, and `MlArray`'s input writers (`f32`/`i32`/`f16`, one shared `filled`) now refuse an input array `CoreML` laid out with non-dense strides instead of copying misaligned. This is a property of how `CoreML` lays buffers out, not of any one model — assume any model output may be padded (ADR-022, ADR-023).
- **`block v0.1.6` future-incompatibility warning** — `cargo clippy --workspace --all-targets` reports a `static of uninhabited type` warning from `block 0.1.6` (pulled in by `gpui 0.2.2 → cocoa/metal/core-graphics2 → block`). The crate is unmaintained (latest published version is still 0.1.6). Will become a hard error in a future Rust release. Resolution requires GPUI to migrate away from the old `cocoa` family to `objc2`. No actionable fix on our side. (`proc-macro-error2` now also appears in the same future-incompat report, pulled in transitively by `ort`/`voice_activity_detector`; same story — no actionable fix on our side.)
- **`E5RT` STL-exception lines on stdout, naming `RNNTJoint.mlmodelc`'s `initial_h`/`linear` shape mismatch — reproduces reliably, root-caused, provably harmless.** Investigated (plan #7, WP8): the two `E5RT encountered an STL exception...` lines reproduce on every run that loads `RNNTJoint.mlmodelc`, including `test-stt-ffi` and `cargo test -p vuho-stt-engine`. Localized precisely by isolation: (1) separating stdout/stderr capture shows the lines are on **stdout** (CoreML's native runtime writes directly to the process's stdout fd — not routed through any Rust `log`/`eprintln`/`Result` path, so no Rust code ever "sees" or masks it), and they print strictly *after* the program's own last `println!` (`=== DONE ===`) — i.e. during static/process teardown, not during load, warmup, or `predict()`. (2) A throwaway probe that loaded **only** `RNNTJoint.mlmodelc` (`ComputeUnits::CpuOnly`) and immediately dropped it with **zero** `predict()` calls still reproduced both lines — ruling out any interaction with the other three models or with real inference shapes. (3) The same probe run against **only** `Preprocessor.mlmodelc` (no `RNNTJoint` loaded at all) produced **zero** `E5RT` lines — pinning the cause specifically to `RNNTJoint.mlmodelc` itself. Conclusion: merely *loading* `RNNTJoint.mlmodelc` — regardless of whether it's ever used for a prediction — causes CoreML's E5RT runtime to internally validate/compile the model's declared `RangeDims`-flexible shape bounds (the "expected 1000" in the message matches the `targets`-length-1000 `RangeDims` ceiling documented in `models.rs`'s doc comment), and that internal validation trips a real shape mismatch baked into the `.mlmodelc`'s own `model.mil` graph — a property of the exported model file (`FluidInference/parakeet-tdt-0.6b-v3-coreml`), not of anything this crate's Rust code does with it. Every actual `Result` this crate observes from `RNNTJoint` predictions succeeds, and `test-stt-ffi`'s transcript output is byte-correct — this is CoreML-internal validation noise, not a masked failure. No actionable fix on our side (would require re-exporting the upstream model). Superseded the plan's original "masked production error" concern, which named `initial_h`/`RNNTJoint`/E5RT only in a doc comment with no reproduction evidence — that reproduction now exists, with root cause, above.
